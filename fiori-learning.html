SAP Fiori — The Basics
What it is, why it exists, and how it's different from old SAP GUI
🌐
What is SAP Fiori?

SAP Fiori is a modern, web-based interface to use SAP on a browser — like opening a website instead of old software. Instead of remembering T-Codes (like MM01), users just click an App tile — similar to a mobile phone app icon.

❌ Old Way (SAP GUI)

  • Open SAP Logon program
  • Type T-Code like MM01
  • Old-style screen opens
  • Only works on desktop

✅ New Way (SAP Fiori)

  • Open a web browser
  • Click an App tile
  • Modern clean screen
  • Works on mobile, tablet, PC
💡
Simple way to explain in interview: "SAP Fiori is like converting old SAP transactions into mobile-friendly web apps. Users click tiles instead of typing T-Codes, but the security rules behind are the same."
🗃️
ECC vs S/4HANA — What's the Difference?
FeatureSAP ECCSAP S/4HANA
DatabaseAny (Oracle, SQL Server, DB2...)Only SAP HANA
SpeedNormalVery fast (in-memory)
InterfaceSAP GUI mainlyFiori first
AnalyticsSeparate reportsReal-time analytics

⚠️
Common confusion: SAP HANA ≠ S/4HANA. HANA is the database. S/4HANA is the ERP application that runs ON the HANA database.
🔐
Security — What Changed, What Didn't?

✅ Still the Same

  • Roles exist
  • Authorization Objects exist
  • PFCG is used
  • SU01 is used
  • Profiles exist

🆕 New in Fiori

  • Catalogs
  • Tiles & Target Mappings
  • Spaces & Pages
  • OData Services (IWSG/IWSV)
  • Launchpad Designer
📌
Key interview point: "Authorization concept is same in Fiori. Roles, objects, PFCG — all same. Only the interface changed from T-Code to App tiles."
Fiori Key Components
Catalogs, Tiles, Target Mappings, Spaces, Pages — explained simply
📦
Catalog — Collection of Apps

Think of a Catalog like a folder that contains apps. You group related apps inside one catalog.

SAP Standard Catalog

  • Created by SAP
  • Cannot be changed
  • Used as reference
  • Example: SAP_MM_BC_PO

Custom Catalog (Z*)

  • You create this
  • Start with Z or Y
  • Used in roles
  • Example: ZCAT_PURCHASING
🟦
Tile — The App Icon

A Tile is the visual icon the user sees on the Fiori launchpad. Like a mobile app icon. Click it → app opens.

Tile TypeWhat it ShowsExample
StaticFixed text, never changes"Create Material"
DynamicLive data that updates"Open Orders: 125" (updates automatically)
CustomMade for special appsCompany-specific tiles
🗺️
Target Mapping — Connects Tile to App

When you click a tile, SAP needs to know "where to go?" — that's what Target Mapping does.

❗
Without Target Mapping: Tile appears ✅ — but clicking it does NOTHING ❌. Always required!

⚡
OData Services — Data Pipeline

OData Services are how Fiori apps talk to the SAP backend. Without them, the app opens but shows nothing.

IWSG — Frontend Service

  • G = Gateway = Frontend
  • Controls app startup
  • Contains S_SERVICE object
  • Without it → app won't start

IWSV — Backend Service

  • V = Backend/Vendor Service
  • Provides business data
  • Contains auth objects
  • Without it → app starts but fails
🧠
Memory trick: IWSG = Gateway (G) = starts the app. IWSV = backend Service (V) = provides data. Both needed for app to work properly.

SAP GUI Apps — Key Difference in Security

SAP GUI apps work exactly like old T-Codes but launched from Fiori. Security setup is different!

❌ Not needed for SAP GUI apps

  • IWSG Service
  • IWSV Service
  • OData activation

✅ What you need instead

  • Transaction Code (e.g. MM03)
  • SU24 authorization defaults
  • S_TCODE authorization object
📌
Custom SAP GUI App: If SU01, PFCG not in Fiori Apps Library — create custom tile with your own Semantic Object (e.g. ZSECURITY_SU01). First check SE93 that T-Code supports "SAP GUI for HTML".

Deployment Types
Embedded vs Central Hub — most asked interview topic
🏢
Embedded Deployment — One System
S/4HANA System (One Server)
Backend
+
Fiori Frontend
  • Frontend and backend on same server
  • Only one role to maintain (simpler)
  • Easier administration — preferred by most customers
  • Most common in S/4HANA projects today
🏗️
Central Hub Deployment — Two Systems
Fiori Frontend Server
↓
S/4HANA Backend Server
  • Frontend and backend on separate servers
  • Need to maintain frontend roles AND backend roles
  • Same user needs access in both systems
  • More complex to manage
  • Used in some older or large enterprise setups
⚠️
In Central Hub: Backend error log is /IWBEP/ERROR_LOG. In Embedded: usually only check /IWFND/ERROR_LOG.
📊

Interview answer: "In embedded, both frontend and backend are in same system, so one role is enough. In central hub, they are separate systems, so I need to maintain frontend role and backend role both and assign to user in both systems."

Troubleshooting Fiori Issues
Most common problems and how to fix them — very important for interviews
🗂️
3 Types of Fiori Issues

1. Launchpad / UI Issues

  • Tile missing
  • Space/Page not visible
  • Wrong navigation
  • Target Mapping missing
  • Catalog not assigned

2. OData / App Issues

  • App won't open
  • Page failed to load
  • HTTP 403 / 404 / 500 error
  • App opens but no data shows
  • Service not activated

3. Data / Database Issues

  • One user sees data, another doesn't
  • Data missing or wrong
  • HANA / CDS view problems

User Group vs User Group for Auth Check

User Group (SUGR)

Just for organizing users. Example: SD team, FI team, MM team. No security restriction.

User Group for Auth Check (S_USER_GRP)

Controls which admins can maintain which users. Admin with INDIA can only edit Indian users. Admin with AUSTRALIA only edits Australian users.

🎤
Interview: "User group is just for categorization. But S_USER_GRP authorization object is used to restrict which security administrator can manage which group of users. This is important for large companies with multiple teams in different countries."
Interview Q&A — Ready Answers
Simple answers in easy English — practice these before your interview
🎤
Fiori Basics
Q
What is SAP Fiori? How is it different from SAP GUI?
SAP Fiori is a web-based interface to use SAP. Instead of opening SAP GUI program and typing T-Codes, users open a browser and click app tiles. The backend authorization — roles, objects, PFCG — stays exactly same. Only the front interface changed.
Q
What is a Catalog in Fiori?
Catalog is a collection of Fiori apps. We create a custom catalog (Z* prefix), copy app tiles and target mappings into it, then assign the catalog to a role in PFCG. Without catalog in the role, user cannot see the apps on launchpad.
Q
What is Target Mapping? Why is it important?
Target Mapping tells SAP which app to open when user clicks a tile. It uses Semantic Object and Semantic Action. If target mapping is missing, the tile appears on launchpad but clicking does nothing. So it is mandatory for every tile.
Q
What is the difference between Groups and Spaces & Pages?
Groups is the old method — all apps show on one page, it looks cluttered. Spaces and Pages is the modern SAP approach — Space is like a business area (e.g. Purchasing), inside it Pages organize apps neatly. SAP recommends Spaces and Pages but Groups still work in old systems.
🎤
OData Services & Deployment
Q
What is the difference between IWSG and IWSV?
IWSG = Frontend service. It starts the application. Without IWSG, tile is visible but app won't open at all.

IWSV = Backend service. It provides authorization objects and business data. Without IWSV, app opens but fails when doing business operation.

Memory trick: G = Gateway = Frontend. V = Backend.
Q
What is Embedded vs Central Hub Deployment?
In Embedded, frontend and backend are on same S/4HANA server. One role is enough. Easier to manage. Most common.

In Central Hub, frontend server and backend server are separate. Need to maintain two sets of roles — frontend roles and backend roles. User needs access in both systems.
Q
What is the difference between CUST and CONF transactions?
CUST (like /UI2/FLPD_CUST) = Client-specific. Changes only affect current client. Security consultants use this.

CONF (like /UI2/FLPD_CONF) = Cross-client. Changes affect all clients in the system. Used by Basis/admin team.
🎤
Application Types
Q
What are the different types of Fiori applications?
There are 5 types:

1. Transactional — do work like create/change/delete (works on any database)
2. Analytical — charts/KPIs/reports (needs SAP HANA)
3. Fact Sheet — search and view object details (needs HANA + Enterprise Search)
4. SAP GUI — old T-Code opened from Fiori tile
5. Web Dynpro — browser app built with ABAP, mainly desktop
Q
What is special about SAP GUI apps in terms of security?
SAP GUI apps don't need IWSG or IWSV services. Instead, authorization comes from the T-Code and SU24 authorization defaults — same as old SAP GUI. S_TCODE authorization object must be in the role. If it's missing, tile shows but app won't open.
Q
What is a Fact Sheet app and how does user access it?
Fact Sheet apps show detailed info about a business object like Sales Order, Customer, Material. User doesn't click a tile — they use the Enterprise Search bar to search. Needs SAP HANA and Search Connectors to be activated via STC01 task list.
🎤
Troubleshooting Scenarios — Most Asked!
Q
User can see tile but app does not open. How to troubleshoot?
Step 1 — Find the application type (from Fiori Apps Library)
Step 2 — Check catalog, role, space assignment
Step 3 — Run SU53 right after error to see what authorization failed
Step 4 — Check IWSG in role (for Fiori apps)
Step 5 — Check S_TCODE in role (for SAP GUI apps)
Step 6 — Check /IWFND/ERROR_LOG for gateway errors
Step 7 — If complex, run STAUTHTRACE
Step 8 — After fix: generate role, do user comparison, test again
Q
User sees "Page Failed to Load". What is the issue?
Most likely an OData service is not activated in the gateway. Steps: Press F12 in browser → check Console for errors → check /IWFND/ERROR_LOG → find the missing service name → go to /IWFND/MAINT_SERVICE → Add Service → select LOCAL/co-deployed → activate → retest.
Q
App opens but shows blank screen. What to check?
This is usually an Annotation/Vocabulary service missing. Open browser F12 → Console → look for HTTP 400 or "vocabulary annotation" error. Check /IWFND/ERROR_LOG. Find the annotation service name → register it in /IWFND/MAINT_SERVICE. Then activate SICF if needed. Retest.
Q
Which transaction do you check first for Fiori authorization error?
Start with SU53 — run it immediately after the user gets the error. SU53 shows the last authorization check that failed. If SU53 is not clear enough, then run STAUTHTRACE for complete trace. For gateway/OData errors, check /IWFND/ERROR_LOG.
🎤
User Admin Questions
Q
What is Reference User? When is it used?
Reference User cannot log in directly. It is assigned to a normal user to give extra authorizations. The main user gets access from both his own role AND the reference user's role combined. Useful when a user needs special extra access without changing their main roles.
Q
How to find why a user is locked?
Check table USR02. Look at the lock status field: 0 = not locked, 32 = locked globally, 64 = locked by admin, 128 = locked due to too many failed login attempts. To unlock: SU01 → enter user → click unlock button.
Q
How to find email address of a user in SAP?
Two steps: First check table USR21 — get the person number. Then check table ADR6 using that person number — it shows the email address. Also, USR21 is the first table that gets updated when a new user is created.
